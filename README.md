# myknowledge

数据分析面试私人知识库。原型阶段：块结构笔记 + 10 域 × 三级分类，纯前端。

## 跑起来

```bash
npm install
npm run dev      # http://localhost:5174
```

## 现在有什么

- 10 个知识域，分类可三级（如 `机器学习模型 / 线性家族 / 逻辑回归`），左侧折叠树 + 域页／分组页逐级下钻
- 侧边栏可编辑：点「✎ 编辑」后可直接改名、加分类、加子分类、删域删分类（删分组不丢笔记，笔记上移）
- 笔记不是 Markdown，是块：`概念卡 / 公式卡 / 对比卡 / 问答卡 / 坑卡 / 步骤卡 / 图片 / 公式 / 提示 / 待补`
- 归位规则：**域（领域）→ 一级分类（话题）→ 二级分类（细分）→ 笔记（一个知识点）**，到叶子为止；
  叶子下面再细分用**标签**切片（分类页按标签过滤），不靠继续加深层级
- 笔记内部默认五段骨架：`核心结论 → 推导 / 细节 → 高频问法 → 我踩过的坑 → 待补`，
  编辑时每个分区尾部有自己的 `+` 按钮，新块只会落进你按的那一段
- **小节可以自己加/删/挪**：`+ 在文末新起一节`、每段尾部的 `⁝ 新小节`（插在这一节后面）、
  标题那行的 `↑ ↓` 整节上下搬、`×` 删掉整节（会先问里面几个块一起删）
- 三种阅读模式：阅读 / 编辑 / 速查（只看卡片）；**阅读态双击任何一块**直接跳到那一块的编辑框，不用先去点「编辑」
  （触屏没有双击，手机上每块右上角会多一个 `✎`，点它同上）
- 编辑态的多行输入框**跟着内容自己长高**，长段落也不用在框里内滚；整页只有一个滚动条
- 三种模式之间来回切一律**回到页面顶端**（双击某块进编辑、新起小节、识图插图这三个入口除外，它们各自把位置定在目标块上）
- 编辑态标签是**一个标签一格**：`+ 标签` 加一格，`×` 删掉；空格子在失焦时自动清掉，不会写进笔记
- 全局聚合页：术语表 / 公式库 / 问答库 / 坑清单，由笔记里的块自动汇总
- AI：AI 收集零散笔记、单块改写、**整篇助手**（指令式重排 + diff 预览）、**问库里**（跨笔记 RAG + 库外标记）、
  **识图**（截图里的公式抄成公式块）
- 示例笔记：`AB 实验 / 方差缩减 / CUPED 方差缩减`

## 图片块

只有一种「图片」块：`{ type: 'image', src, text }`，`src` 存链接、`text` 是图注。

**为什么不把图片塞进数据仓库**：数据仓库是 private，`raw.githubusercontent.com` 的链接在 `<img src>` 里带不了 token
（img 标签没法加 `Authorization` 头），走 Contents API 取 base64 再转 blob 又慢又得自己缓存 —— 一页 5 张图就是 5 个慢请求。
所以图片只存 URL，走第三方图床。

**推荐图床：GitHub 自己的 user-attachments**（免费、永久、不限量）：

1. 在任意 issue 的输入框里 Ctrl+V 拖入/粘贴截图
2. 等它自动上传，输入框里会生成 `https://github.com/user-attachments/assets/xxxxxxxx-...`
3. 把这段链接复制进图片块

任何公开可直链的图片地址都能用（图床 / CDN / 自己博客）。注意私链、防盗链、需要登录才能看的链接会加载失败，
这时块会降级成「图没加载出来，链接可能失效或不许外链 + 打开原图」，不会把整页撑坏。

**图注会参与搜索**：检索只取 `text`（图注），`src` 不参与 —— 所以给图起个能搜到的名字有用。

### 识图：截图里的公式不用手打

DeepSeek 看不了图，所以视觉模型是**单独一份配置**（同一个 `myknowledge.ai` 对象里的 `vision` 字段），
默认填好智谱的 `glm-4v-flash`（免费）：顶栏 ✨ → 设置 →「视觉模型」填 Key，点「测试视觉模型」验证。

识图是一个**统一弹窗**，三个入口都进同一个：

| 你在哪 | 怎么进 | 落点 |
| --- | --- | --- |
| 编辑态任意输入框 | 截图后直接 <kbd>Ctrl</kbd>+<kbd>V</kbd> 粘贴 | 光标所在那一段的末尾 |
| 每段下面的「在此段加」 | 点 `📷 识图` | 你按的那一段的末尾 |
| 图片块里 | 点「🔍 识图 · 把图里的式子抄成公式」（有 `src` 就自动读那张） | 该图片块的下一格 |

弹窗里图怎么进去都行：拖进虚线框、点「选图片文件」、`Ctrl+V` 粘贴、或点「读剪贴板」。
弹窗顶部会写明**插到哪一段**，落块前不会动数据。

拿到结果**先预览再落块**：识别成公式时给一个可编辑的 LaTeX 输入框 + KaTeX 实时渲染（错一个下标能当场改），
识别成文字时给一个多行框。确认后点「+ 插入公式块」/「+ 当段落插入」，不想认了按「换一张」。

**图本身不会被存进笔记**：它只是被读一遍，读出来的块才是留下来的东西。所以「本地截图 → 公式块」这条链路
不需要图床、不需要 base64 塞 localStorage（那会撑爆 5 MB 配额，同步也会跟着爆）。
真想留图当原始凭证，就按上面「图片块」那节先用 `user-attachments` 传一张，再把链接粘进图片块。

几个坑：

- 模型读图会认错符号（`\bar` 和 `\hat`、`p` 和 `ρ`），落块前一定对一眼
- `user-attachments` 这类第三方链接可能不许跨站读图（CORS），这时会提示「这个链接不让别的网站读图」，
  改用拖入/粘贴本地截图
- 「读剪贴板」要在 HTTPS 或 `localhost` 下、并授权剪贴板才有用；网页里 **`Ctrl+V` 粘贴永远是最稳的路**
- 图会先缩到长边 1600 px、转 JPEG 再发，别拿它当原图备份用

## 数据存哪

原型阶段：浏览器 `localStorage`，键名 `myknowledge.v3`（整篇笔记的 `blocks` 数组直接序列化进去），
改完 700ms 自动保存，刷新不丢、`dist/` 与 `node_modules/` 不入库。

局限：清站点数据即丢、手机和电脑不同步、没有历史版本、没有账号。

## 云同步（可选）

顶栏 ☁ 按钮里填 GitHub 私有仓库 + fine-grained token，即可多端同步：

- 数据落在 `owner/repo/branch/path` 指定的索引文件（默认 `myknowledge-data` / `main` / `kb.json`）以及它旁边的 `notes/` 目录
- token 只要有该仓库的 **Contents: Read and write**，只存本机 localStorage，不经过任何第三方
- 启动时先拉 `kb.json` 和 `notes/` 的文件列表，只下载 `sha` 变了的域文件；编辑后 2s 防抖上传，只写内容真的变了的文件
- 手机和电脑同时改，本地改过的域不吃远端（本地赢），下次上传覆盖远端

### 为什么按域拆文件

```
myknowledge-data/
  kb.json              # 分类索引：只有 domains + topics
  notes/
    d1.json … d10.json # 每个域一个文件：该域全部笔记
    _orphan.json       # 兜底：所属域被删掉的笔记
```

一条笔记平均约 5 KB（当前 1 篇 17 块 = 5.2 KB），10 个域 120 个分类的索引约 24 KB。

关键瓶颈是 GitHub Contents API **没有增量写入**：每次保存都要重传整个文件 + 一个新 commit。
按域拆之后，写一篇笔记只动 `notes/dX.json` 一个小文件，而不是整份库：

| 场景 | 拆之前 | 拆之后 |
| --- | --- | --- |
| 改一篇 AB 实验的笔记（300 篇时） | 重传 ≈ 1.5 MB | 重传该域 20 篇 ≈ 100 KB |
| 加一个分类 | 重传整份库 | 只重传 `kb.json` |
| 改一篇笔记产生的 commit | 1 个，diff 里混着所有域 | 1 个，diff 只有那个域 |

为什么不按**笔记**拆：一次编辑会跨多个文件、多个 commit（索引 + 笔记），冲突面反而更大。
为什么不拆更细（按分类）：目录会膨胀到几百个文件，每次同步的 `listDir` + sha 比对开销超过收益。

怎么判断「内容真的变了」：每个文件算一个 FNV-1a 指纹，指纹只看**真内容**
（`schema` + `domainId` + 笔记里的块/标题/标签），刻意**不含** `updatedAt` / `version` 这类每次都变的字段，
推上去的文件体里也不再写文件级 `updatedAt`。所以「点开又关掉」「加了个空格标签」这类操作
不会在云端留 commit —— 只有笔记内容真的改了，才推它所在域的那一个文件。
旧版本存下的指纹（含时间戳）也认，升级后第一次同步不会把所有域文件重推一遍。
`JSON.stringify(data, null, 2)` 两空格缩进，`git diff` 肉眼可读；上传前先取 `sha` 防 409，冲突自动重试一次。

## AI 助手（可选）

顶栏 ✨ 打开，五处用法：

- **收进来**：贴一段零散笔记 → AI 挑分类、切成知识块、按「核心结论 / 推导 / 高频问法 / 我踩过的坑 / 待补」归位 → 先看预览，确认后才写入新笔记
- **单块改写**：编辑模式下每个块右上角 ✨ → 润色 / 扩写 / 拆成知识块 / 造高频问法 / 造踩坑卡 → 先看预览，点「采用」才替换
- **整篇助手**：笔记顶栏「✨ 整篇助手」→ 说一句要求，模型返回一串「改 / 新 / 删」操作，逐条看完勾选才写回
- **识图**：编辑态 `Ctrl+V` 粘贴截图 / 每段「📷 识图」/ 图片块里的识图按钮 → 截图里的公式转成 LaTeX，改对了再插成公式块
- **问库里**：直接提问，跨整个知识库回答。AI 先用你的笔记答，笔记里没有的部分会单独标成「【库外】」；勾上「只查我的笔记」就锁死在库内，答不出来会直接说没有

「问库里」是纯前端 RAG，没有后端也没有向量库：

1. 问题先本地检索（中文切二字、英文按词，标题 / 分类路径 / 正文分别加权）挑出最相关的至多 10 篇，上限约 18,000 字符
2. 把这几篇压成「标题 + 分类路径 + 每块要点」塞进提示词，让模型先依据这些资料回答，每条结论标 `[1]` 这样的来源编号
3. 资料不够、但模型确实知道的，另起一段以「【库外】」开头 —— 界面上渲染成灰色虚线块，提示「AI 的外部知识，不是你笔记里的内容」，一眼能分清哪句有出处
4. 点答案里的编号或下面的笔记标签，直接跳到那篇笔记
5. 一篇都没命中时退回最近改过的 6 篇，并在答案下方标注「没找到直接相关的笔记」

「只查我的笔记」开关（记在 `myknowledge.askStrict`）：换一套严格提示词、`temperature` 降到 0.1、禁止输出「【库外】」段。适合面试前确认「这个知识点我笔记里到底写了什么」。

问答也是一次普通的模型调用，只是上下文从「你贴的内容」换成了「检索出来的笔记」。流式输出，可以中途「停止」。

配置：面板里「设置」填 Base URL、模型、API Key。

- 默认 DeepSeek：`https://api.deepseek.com` + `deepseek-chat`
- 任何 OpenAI 兼容接口都能用（把 Base URL 换成对应地址、模型名换成对应模型）
- **视觉模型是单独一份配置**，只给识图用；不填不影响上面这些文字功能
- Key 只存本机 `localStorage`，直连服务商，不经过任何第三方；换设备要重填
- 拿 Key：<https://platform.deepseek.com/api_keys>；识图另拿：<https://open.bigmodel.cn/usercenter/apikeys>

### 追问会带上文

聊天上下文本身支持多轮，但**检索**原先只看当前这一句，于是「那它的假设是什么」这种追问会检索偏 —— 拿这句去搜，
命中的是「假设检验」而不是上一轮在聊的 CUPED。

现在检索会把上一轮的提问一起带上，但只算**半票**：

| 命中位置 | 当前句 | 上一轮问题 |
| --- | --- | --- |
| 笔记标题 | 6 | 3 |
| 分类路径 | 3 | 1.5 |
| 正文命中 | 1 | 0.5 |

只补**上一轮**（不是整个历史），且上一轮已经出现过的词不重复计。这样「刚才聊的话题」能把你带回正确的语境，
又不会盖过「这一句真正问的东西」。

### 答案存成笔记

每条回答下面有「＋ 存成笔记」，点开先出**预览**，不直接写。落哪儿分两条路：

**新建一篇**

1. 选落到哪个分类（下拉框列出全部叶子分类，按域分组），默认落在被引用的第一篇笔记的分类
2. 预览区用真实的卡片渲染，就是你存进去以后的样子
3. 回答里带「【库外】」段时，多一个「也带上库外那段」的勾选框，**默认不勾** —— 库外是 AI 外推的，
   勾了会先插一张黄色的「自己核一遍再当结论用」提示卡，再把库外内容拆成正文段落
4. 点「写入新笔记」→ 立刻跳到新笔记，标题取你的提问（太长会截断加 `…`）

**写进已有笔记**

1. 「写进」下拉选一篇已有笔记（列表带分类路径），默认是被引用的那篇
2. 「加到这段」下拉选落到哪一段（核心结论 / 推导 / 高频问法 / 我踩过的坑 / 待补），默认高频问法 ——
   问出来的东西本来就是问答卡，放这一段最自然
3. 点「写进这篇」→ 插到那一段的**末尾**（不是文末），然后跳到那篇笔记

两种都存成一张「问答卡」：问题是你的原话，答案在库内段末尾附一行 `来源：[1] 标题　[2] 标题`。
问答卡在笔记里是默认折叠的（和阅读态一致），这样一篇笔记里塞多轮问答也不会太长。

### 整篇助手

笔记顶栏的「✨ 整篇助手」把它当一份稿子重排，不是逐块改。说一句要求（或者点现成的预设，比如
「核心结论拆成 2-3 条，每条一句断言」），模型返回一串**操作**，界面逐条列出来：

| 标记 | 含义 | 默认勾选 |
| --- | --- | --- |
| 保留 | 原样不动 | —（不可取消，只是展示） |
| 改 | 改写已有块，上下并列「原文 / 改成」两版 | 勾 |
| 新 | 新增块，标出要落进哪一段 | 勾 |
| 删 | 删掉已有块 | **不勾** |

动手前能看清每一处变化，勾上的才写进去。几条设计上的取舍：

- 模型只给 `keep / replace / add / drop` 四种 op，**指令没提到的块一律 keep** —— 不会因为一次「补两句」被顺手润色整篇
- 模型给的 id 不存在、把 `add` 写成 `replace`、同一个块重复出现，都会被掰正（重复的丢掉，指向不存在的 id 降级成新增）
- 模型漏列的原有块会**自动保留**，不会悄悄吃掉你的内容
- 段落标题由程序按五个固定段重新生成，你自己起的小节名会被并回去（弹窗里会先提醒是哪几节）；写完没内容的段不会留下空标题
- 模型要给新标题时会先告诉你「标题会改成 X」，不勾任何改动就不会改

## 部署

推 `main` 触发 `.github/workflows/deploy.yml`：构建后把 `dist/` 强制推到 `gh-pages` 分支
（用 `peaceiris/actions-gh-pages@v4`，不需要 Pages API 权限）。

首次启用只需一次（GitHub 现在不给 `GITHUB_TOKEN` 建站点的权限，必须手动点）：

1. 仓库 **Settings → Pages**
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `gh-pages`，目录选 `/ (root)`，Save
4. 等 1 分钟，访问 `https://cccyyy527.github.io/myknowledge/`

注意：

- Free 账号下 Pages **只支持公开仓库**，所以本仓库是 public；笔记正文不在这个仓库里
- 站点是公开可访问的静态页面，但**数据要靠浏览器里的 token 才能拉取**，别人打开只会看到空库
- 之后每次推 `main`，`gh-pages` 会被覆盖更新，Pages 自动重新发布

## 结构

```
src/
  lib/seed.js      # 10 域、三级分类、示例笔记
  lib/store.js     # 内存状态 + localStorage 持久化 + 统计/搜索/聚合 + 目录增删改
  lib/remote.js    # GitHub Contents API：单文件读 / 写 / 列目录
  lib/split.js     # 快照 ⇄ 按域拆开的文件（索引 + notes/dN.json），内容指纹
  lib/sync.js      # 增量 pull / push 编排：只传变了的文件，sha 冲突重试
  lib/ai.js        # AI：提示词 / 块归一化 / 自动落位 / 单块改写 / 整库问答 / 识图 / 整篇改写
  lib/retrieve.js  # 本地检索：从笔记里挑相关篇目，拼成问答资料
  components/BlockView.vue   # 块 → 知识卡渲染
  components/BlockEdit.vue   # 块 → 编辑控件（公式带实时预览、图片带识图入口）
  components/OcrDialog.vue   # 识图弹窗（拖入 / 选文件 / 粘贴 / 读剪贴板 → 预览 → 落块）
  components/SyncDialog.vue  # 云同步配置面板
  components/AiPanel.vue     # AI 面板（收进来 / 问库里 / 设置 / 视觉模型）
  components/AiAsk.vue       # AI 跨库问答（检索 + 引用 + 存成笔记）
  components/AiBlockDialog.vue # AI 单块改写弹窗
  components/AiNoteDialog.vue  # AI 整篇助手（操作列表 → diff → 勾选写入）
  pages/           # 首页 / 域 / 分类（可含下级）/ 笔记 / 聚合 / 搜索
```
